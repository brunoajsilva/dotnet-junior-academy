Último dia: entregas o projeto e fazemos uma review em conjunto. Não há tarefas novas. O que se revê é o que construíste até ao fim do dia 5.

## O que entregas

### A solução BankingApp

O código dos cinco projetos, com as migrations, a compilar sem avisos e com os testes a passar.

### O plano final

As user stories que escolheste, as estimativas, os riscos, as dependências, o que ficou de fora e o que mudou ao longo da semana.

### A coleção do Bruno

Um pedido por endpoint que implementaste, para que o projeto possa ser experimentado sem ler o código.

## Como corre a review

1. **Demonstração** Mostras a API a funcionar e explicas o percurso de um pedido, do cabeçalho Authorization à base de dados.
2. **Review do código** Percorremos o código em conjunto. Há perguntas de «porquê» sobre as decisões que tomaste.
3. **Plano contra realidade** Comparas o que estimaste com o que aconteceu e dizes o que farias diferente.

## Plano contra realidade

1. Quantas horas estimaste no total e quantas gastaste?
2. Qual foi a user story em que mais erraste a estimativa? Porquê?
3. O que cortaste, e quando decidiste cortar?
4. O que farias diferente no planeamento?

## Perguntas que podem surgir na review

1. Porque é que a interface do repositório fica na Application e a implementação na Infrastructure?
2. Porque guardamos o hash da password e não a password?
3. O que acontece se a gravação da transferência falhar a meio?
4. Porque devolve o sistema not\_found e não forbidden para a conta de outro cliente?
5. Que parte do teu código mudarias se trocasses SQL Server por outra base de dados?

## Mostra o projeto a funcionar

Se quiseres, podes acrescentar uma interface à demonstração. Não é obrigatório, não conta para a avaliação e não substitui a coleção do Bruno. Serve para veres e mostrares a API a funcionar com os teus olhos. Pede-a a um assistente de IA com o prompt abaixo e revê o resultado: o código é teu, por isso tens de o perceber.

1. Exporta o OpenAPI da tua API (o ficheiro swagger.json, a partir do Swagger) e guarda-o.
2. Copia o prompt, preenche os campos entre parênteses retos (nome, endereço e as tuas user stories) e anexa o OpenAPI.
3. Corre o resultado e experimenta cada user story, com um caso de sucesso e um de erro.
4. Compara o painel «Pedidos à API» com a tua coleção do Bruno.
5. Se algo falhar, pergunta-te primeiro se o erro está na interface ou na tua API.
